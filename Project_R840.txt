Project Status: AspeQt R: Device Port (Revised)
Current Phase: Integration & Roadblock Mitigation
We have successfully ported the logic, verified the binary drivers, and corrected the boot protocol. We are now facing strict timing constraints within the existing SIO architecture.

1. What We Have Fixed & Completed
[COMPLETED] Boot Protocol Logic:

Fixed RDevice::handlePollType1 to send the required 12-byte Boot Block instead of a 4-byte status.

Removed improper writeComplete() calls for boot commands ($3F, $21, $26) to match raw SIO protocol.

[COMPLETED] Driver Binary Verification:

Verified that rdevice_handler.h contains the exact byte-for-byte binary data from the working FujiNet firmware (850relocator.bin and 850handler.bin).

[COMPLETED] Relocator Implementation:

Added handleDownloadRelocator() to support Command $21.

[COMPLETED] Timing Adjustments:

Added specific msleep() delays in RDevice to allow the Atari OS time to process the boot loader.

2. Current Roadblocks (The "SIO Barrier")
These are issues in the existing AspeQt architecture that may interfere with our new RDevice.

Roadblock A: The Hardcoded "Echo" Delay

Issue: serialport-unix.cpp (and Win32) forces a usleep(500) delay after every command frame when using software handshaking.

Risk: This delay + our new RDevice delay might exceed the Atari's boot timeout window, causing the boot to fail silently.

Roadblock B: Aggressive Buffer Flushing

Issue: readCommandFrame() calls tcflush (flush input) at the start of every cycle.

Risk: The 850 boot sequence is fast ($21 Relocator -> $26 Handler). If the PC is slow to loop, the $26 command might arrive, get buffered by the OS, and then immediately deleted by tcflush before AspeQt reads it.

Roadblock C: Stream Mode Incompatibility (Command $58)

Issue: The SioWorker loop expects valid SIO Command Frames (5 bytes + Checksum) forever.

Risk: If we enable "Stream Mode" ($58), the Atari sends raw characters. SioWorker will reject them as checksum errors. We cannot test concurrent mode yet.

3. The Correction Plan (Immediate Steps)

We need to register the device in sioworker.cpp so it actually responds.

#include "rdevice.h"
// Inside SioWorker::start()

Step 2: The "Smoke Test" (Boot Verification)
We test without modifying the roadblocks first. If it works, great. If not, we apply mitigations.

Action: Launch AspeQt in Linux -> Boot Atari (Emulator or Hardware).

Success Criteria:

Log shows Command: 3F (Poll) -> ACK.

Log shows Command: 21 (Relocator) -> ACK -> Data sent.

Log shows Command: 26 (Handler) -> ACK -> Data sent.

Atari boots to READY.

Step 3: Roadblock Mitigation (If Boot Fails)
If the boot fails (Atari hangs or ignores R:), we modify serialport-unix.cpp:

Fix A: Comment out QThread::usleep(500) in readCommandFrame.

Fix B: Comment out tcflush(mHandle, TCIFLUSH) in readCommandFrame (or make it conditional).

4. Next Testing Steps (Post-Boot)
Once the driver is loaded:

Test 1: Block Mode Command ("The Echo")

Method: Use BASIC.

Basic
10 OPEN #1,12,0,"R:"
20 PRINT #1;"AT"
30 GET #1,A:? CHR$(A);:GOTO 30
Expectation: RDevice receives the block, buffers "AT", processes it, and returns "OK" in the next block read.

Why: This uses standard SIO commands ($57 Write / $52 Read), bypassing the "Stream Mode" roadblock.

Test 2: Terminal Mode (Safe)

Method: Run BobTerm or Ice-T but configure it for "Block Mode" (not Concurrent/Stream).

Expectation: You should be able to type ATDT bbs.foobar.com and see a connection.

Test 3: Stream Mode (The Fail Case)

Method: Try to switch to "Concurrent Mode" (Command $58).

Expectation: FAILURE. The SioWorker will likely crash or spam errors. We will address this in a future architectural overhaul.
